# ハードAIナビ 運用ルール

コンシューマー向けハードAI（AIペット・家庭用ロボット・AIガジェット・個人向け小型ヒューマノイド等）を紹介するアフィリエイトメディア。
生成は `node build.mjs`（依存ゼロ。npmレジストリが使えない環境でも動く）。記事は `content/articles/*.md`。

## 記事の絶対ルール（自動執筆の事故防止）

1. **出典なしの事実は書かない。** 価格・発売日・仕様は、メーカー公式かプレスリリースを WebFetch で開いて確認した値のみ。検索結果のスニペットだけで書かない。
2. **価格には確認日を入れる。** 冒頭の注記に「価格の確認日：YYYY年M月D日」。本文の価格は出典リンクを付ける。
3. **確認できなかった項目は「未確認」と書く。** 推測で埋めない。出典同士が食い違う値は使わず、片方を採るなら理由を書く。
4. **実機を使っていない。** 「使ってみた」「触った感想」「口コミ」風の文章、架空のレビュー・評価点を書かない。使用感を推測で述べない。
5. **PR表示は自動挿入される**（テンプレート）。記事側で消さない。アフィリエイトリンクの報酬で順位・評価を変えない。
6. **医療・効果の断定、「No.1」「最安」等の根拠なき最上級を書かない。**
7. 値上げ・販売終了など、日付で状況が変わる情報は、日付を表に入れて明記する。
8. frontmatter 必須: title / description / date / updated / sources（`category` は任意：AIペット / 人型ロボット / 購入ガイド）。本文にはURLつき出典を入れる（ビルドが検査する）。

## アフィリエイトリンク

`site.config.json` の `amazonTag` / `rakutenId` を設定後、商品リンクに付与する。未設定の間は公式リンクのみ。リンクには `rel="nofollow"` を付ける（変換器が自動付与）。

## 更新

価格は変動する。既存記事は月1回、公式ページで再確認し、`updated` と本文の確認日を更新する。

## 動画・商品リンク（frontmatter）

- `videos: [YouTube動画ID|タイトル|投稿元の確認状況, ...]`（区切りは `|`、タイトルにカンマは使わない）。記事内に「動画で見る」としてクリック再生で埋め込まれる。動画ページを開いて投稿元（公式チャンネルか）を確認できた場合のみ、確認状況に「公式チャンネル」と書く。できなければ「投稿元は未確認」。
- `products: [商品名, ...]`。Amazon・楽天の検索結果ページへの通常リンクを「商品ページを探す」として自動生成する。取り扱いのない商品には付けない。
- メーカーの商品写真は、利用許諾（プレスキット規約、Amazon PA-API 等）を確認できたものだけ使う。無断での取り込み・再配布はしない。

## アフィリエイトタグの自動付与

`site.config.json` に `amazonTag`（アソシエイトのトラッキングID）を入れると、`amazon.co.jp` へのリンクすべてに `tag=` が付く。`rakutenId`（楽天アフィリエイトID）を入れると、`rakuten.co.jp` へのリンクが `hb.afl.rakuten.co.jp` の汎用リンクに包まれる（登録後に実際のリンクで計測できるか確認すること）。空の間は通常URLのまま。いずれも `rel="nofollow sponsored"` が付く。

## 画像・動画の取り扱い

- 製品画像は、メーカー公式サイトのものを、出典（会社名とURL）を記事内のキャプションに明記したうえで使う（運営者の許可あり）。記事本文では `![説明](/images/xxx.webp "出典名|出典URL")` と書く。`public/images/` にWebPで保存する（幅1000px程度、`convert in -resize '1000x>' -quality 82 out.webp`）。
- 人物（モデル）が写っている画像は使わない。画像がどの製品か公式ページ上で確認できないものは使わない。
- 動画は `node check-video.mjs <ID>` で投稿元を確認し、公式チャンネルなら「公式チャンネル（名前）の投稿」と書く。確認できなければ「投稿元は未確認」。
- `image` / `imageCredit`（出典名|URL）はトップ・一覧のカード画像とOGP画像に使われる。

## CTA（frontmatter と本文ディレクティブ）

- `cta: [製品名|ボタン文言|リンク先URL|価格|補足|shops|バッジ|画像パス|紹介文|特徴（／区切り）|向いている人, ...]`（区切りは `|`、項目の区切りは「, 」。`shops` を入れるとAmazon・楽天の検索リンクも付く。不要な項目は空にする）。リンク先は原則、公式ストア・公式ページ。CTAカードは**製品紹介が主役**で、価格は補助（「価格の目安」）として小さく出す。紹介文・特徴・向いている人は、公式ページで確認した事実だけで書く。
- `cta` を付けると、結論の直後の確認カード、PC右側の追従カード、スマホの下部固定バー、記事末尾のCTAブロックが自動で出る。
- 比較記事は `ctaMode: inline` にして、本文で `@cta 製品名`（その位置にCTAカード）と `@video 動画ID|タイトル|投稿元の確認状況`（その位置に動画）を使う。構成は「結論→比較表→おすすめ順に1製品ずつ（画像・動画・CTA）」。
- おすすめ順の基準は本文に明記する（費用の低さ・始めやすさなど）。報酬の有無・多寡で順位を決めない。
- 緊急性の訴求（値上げ予定など）は、公式発表がある事実だけを使う。「今だけ」「残りわずか」などの煽りは書かない。

## 販売状況の確認（必須）

記事を書く前に、公式の購入ページに「販売終了」「受注終了」「在庫切れ」の表示がないか確認する。あれば結論の冒頭に書き、CTAのバッジにも出す（例：aibo ERS-1000は2026年6月25日に国内販売終了を発表）。販売終了の製品に、購入を促すCTAは付けない（公式サイトへのリンクにとどめる）。

## 訂正

記事に「訂正履歴」の節は設けない。誤りに気づいたら本文を直し、`updated` を更新する。

## 在庫の確認

ユカイ工学ストアなどShopifyのストアは、ページ上の「在庫切れ」の文字がテンプレートとして常に含まれる。在庫は商品ページの `.js`（例：`https://store.ux-xu.com/products/qoobo.js`）の `variants[].available` で確認する。

## カテゴリ詳細ページ（比較記事を兼ねる）

- `content/categories/*.md` が `/category/<slug>/` になる。トップのFV（商品カテゴリ一覧）、ナビ、フッター、記事一覧の「比較ページへ」リンクの起点。
- frontmatter: `title / description / name / summary / products（記事スラッグ、価格の低い順など基準を本文に明記）/ priceRange / icon / order / updated`。
- 本文に `@@table`（自動の比較表）と `@@products`（各製品の節）を置く。製品の節は、各記事の「特徴・仕様・費用・買う前に確認したいこと」などの節を自動で埋め込み、その下にCTAカードを出す。記事側の `hubTitle:` が節の見出しになる。`hub: all` の記事は全節を埋め込む（複数製品を扱う記事）。
- 製品を深く書くときは、**元の記事を書き込む**（カテゴリページに自動反映される）。順位の基準にアフィリエイト報酬を使わない。
- 旧 `ai-pet-robot-comparison` は `/category/pets/` へ恒久リダイレクト（`vercel.json`）。

## 掲載対象（AI搭載のみ）

- 公式ページでAI・学習・成長などの機能が確認できない製品は掲載しない（例：猫舌ふーふー、甘噛みハムハム、fufuly、Qoobo、toio）。該当記事は `content/archive/` に退避してあり、ビルド対象外。URLは `vercel.json` でカテゴリページへリダイレクト。
- 新しい製品を足すときは、記事内に「AIに関する公式の説明」を必ず書く。確認できない場合は掲載を見送る。
- 大カテゴリ配下のジャンルは、frontmatter の `parent: <大カテゴリのslug>` で作る。1ジャンルに2製品以上そろってから分ける。
